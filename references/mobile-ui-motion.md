# 手机 UI 动效工程手册：让界面切换"丝滑"

本文件固化手机录屏段（竖屏 9:16）的界面动效实现方法，参数来自对参考视频《夜景模式》
（720×1280，30fps）的逐帧拉片。配套脚本 `scripts/ui_motion.py` 已把缓动、时长、帧数、
打字节奏与倒计时做成可调用函数，本文件讲清原理与落地路径。做手机界面段时先读本文，
再用脚本取数；电脑桌面段仍以 `style-guide.md` 为准。

## 1. 为什么看起来"丝滑"：五条底层原则

参考视频的"丝滑"不是某个炫技转场，而是一组工程纪律的叠加。对照执行：

1. **时长极短，绝不拖沓。** 所有过渡都在 0.2–0.4 秒（6–12 帧）。超过 0.5 秒就会
   让人觉得"慢"。这是第一原则，先把时长压下来，再谈曲线。
2. **缓动而非匀速。** 进入类动画用 ease-out（先快后慢，像物体落定），退出类用
   ease-in（先慢后快，像被抽走）。匀速线性运动是"假"的最大来源。
3. **统一视觉语言。** 全片只用一套圆角卡片、毛玻璃（半透明深色）、同一组图标与
   字体，横幅、锁屏通知、列表卡片三者同源，观众潜意识里觉得"这是同一个系统"。
4. **浮层不打断。** 通知横幅从顶部滑入时，下层的相机倒计时、取景、手持晃动全部
   继续，不暂停、不跳变。真实系统就是这样，打断会立刻暴露"合成"。
5. **真实反馈。** 按键按下瞬间高亮、字符逐个出现且节奏不均、取景有持续手持晃动、
   快速移动有运动模糊。这些"无用"的细节共同支撑"这是真录屏"。

## 2. 缓动函数与统一动效参数

`ui_motion.py` 内置 12 种缓动，常用选择：

- 进入/展开（键盘上滑、卡片放大、列表淡入）：`ease_out_cubic`、`ease_out_quad`
- 退出/收缩（键盘下滑、App 关闭、横幅收起）：`ease_in_cubic`
- 系统级卡片展开（App 打开）：`ios_ease_out`（cubic-bezier 0.32,0.72,0,1）
- 通知落定（需要轻微过冲回弹）：`ease_out_back`

实测动效规格（脚本 `MOTION_SPEC` 原值，30fps；格式为"时长 / 帧数 / 缓动"）：

- 键盘上滑：0.27s / 9 帧 / ease_out_cubic
- 键盘下滑：0.25s / 8 帧 / ease_in_cubic
- App 打开：0.30s / 9 帧 / ios_ease_out
- App 关闭：0.40s / 12 帧 / ios_ease_in
- 多任务横滑：0.30s / 9 帧 / ease_out_cubic
- 横幅滑入：0.35s / 11 帧 / ease_out_back
- 横幅停留：1.80s / 54 帧 / 不变化
- 横幅收起：0.30s / 9 帧 / ease_in_cubic
- 锁屏通知进入：0.35s / 11 帧 / ease_out_back
- 列表项淡入：0.25s / 8 帧 / ease_out_quad
- 气泡发送：0.20s / 6 帧 / ease_out_quad

取数命令：`python scripts/ui_motion.py frames app_open` 输出每帧的时间与缓动进度，
直接作为关键帧百分比；`python scripts/ui_motion.py spec` 列出全表。

## 3. 打字与键盘系统（真实感核心）

打字是手机段最容易露馅、也最能取信的部分。参考视频做对了四件事：

### 3.1 键盘上滑与收起

- 键盘从屏幕底部沿 ease-out 曲线滑入（约 0.27s），同时输入框区域被整体上推，
  不是键盘简单盖住画面。收起为反向 ease-in（约 0.25s）。
- 键盘本体：iOS 风格圆角按键、浅灰底，含 shift（上箭头）、123、emoji、空格、
  蓝色"发送"键；按下的键在那一帧变深色高亮，松手恢复。

### 3.2 拼音输入法状态机（关键）

中文不是直接蹦出来，而是走完整的输入法状态，分三种视觉形态：

1. **未确认拼音**：输入框里显示带下划线的高亮拼音（如 `ba`、`di'y`），
   键盘上方的候选词栏实时显示对应候选（如"搬新家 搬"）。
2. **选词/上屏**：确认后拼音转为黑色中文，下划线消失，候选栏刷新。
3. **逐字符 + 真人节奏**：字符逐个出现，间隔不均匀，有连打、停顿、退格、选词。

脚本 `typing_schedule()` 生成逐字符出现时间：`base_cps` 控制平均速度（中文手机打字
经验值 4–8 字/秒），`jitter` 给每个间隔加随机抖动，`pause_every` 每隔若干字插入
一次长停顿（模拟思考/选词）。命令：

```bash
python scripts/ui_motion.py type "搬新家第一晚" --seed 3
```

`pinyin_states()` 给出"未确认拼音（带下划线）→ 上屏中文"的状态时间线，制作时据此
切换文字颜色与下划线。退格要真实：偶尔删掉一两个字再重打，比一路顺打更像真人。

### 3.3 文字一律后期叠加

键盘与输入框底图由 AI 生成或自行绘制，但所有拼音、候选词、上屏文字都在后期按
`typing_schedule` 的时间点逐帧叠加，AI 不直接生成中文。

## 4. 应用切换与多任务

### 4.1 多任务（最近任务）界面

- 进入后各 App 以大圆角卡片横向排列，居中卡片最大、两侧卡片带景深缩小，
  背景做模糊处理，底部 dock 常驻。
- 横向滑动切卡片（约 0.3s ease-out），卡片随手指位移、松手吸附到居中位置。

### 4.2 App 打开（卡片缩放展开）

- 从桌面图标位置出现一个带圆角的小卡片，窗口内容已在卡片内，卡片平滑放大到
  全屏，圆角逐渐消失，背景是桌面图标。约 0.3s，用 `ios_ease_out`。
- 用 `eased_rect()` 对卡片矩形 (x,y,w,h) 整体插值，圆角半径同步从大到小插值到 0。

### 4.3 App 关闭（卡片化收缩，与打开互逆）

- 当前页面整体收缩为带圆角的卡片（内容完整保留，只是卡片化），向边缘/下方缩小
  消失，露出下层界面。约 0.4s，用 `ios_ease_in`。打开与关闭互为逆过程，方向和
  曲线要对应，观众才会觉得"窗口有来有回"。

### 4.4 滑入式分屏过渡

- 新页面从屏幕一侧滑入、旧页面被推到另一侧（过程中两页同屏、新页带圆角），
  用于相邻 App 间的快速切换，比缩放更干脆。

## 5. 消息弹出：横幅、锁屏、列表三种

三种"消息弹出"视觉同源（半透明深色毛玻璃圆角卡片），但出现场景和动画不同，不要混用。

### 5.1 顶部横幅（使用 App 时）

- 在相机等界面上，半透明深色毛玻璃横幅从顶部滑入（约 0.35s，带轻微过冲回弹），
  含 App 图标、发送者、时间（"现在"）、内容摘要（如"私信了你：[图片]"）。
- 不打断下层：取景、倒计时、晃动继续。停留约 1.8s 后向上收起（约 0.3s）。
- 脚本 `banner_timeline()` 给出 in/hold/out 三段时间区间。

### 5.2 锁屏通知（堆叠）

- 锁屏 = 大时钟 + 日期 + 壁纸（月夜黑猫）；通知是半透明深色毛玻璃圆角卡片，
  含 App 图标、来源、右侧时间、标题与正文。
- 新通知从顶部滑入时，已有卡片整体下移让位，形成纵向堆叠（实测堆叠到 3 条）。
- 用 `lock_notice_in` 规格；旧卡片的位移与新卡片进入用同一条 ease-out 曲线，
  保证"让位"和"进入"同步。

### 5.3 列表内新消息/评论

- 新评论从列表底部淡入（半透明→不透明，约 0.25s），同时把已有内容向上推。
- 自己发送的气泡从输入位置弹入并轻微放大（约 0.2s）。
- 列表上推与淡入同时发生，不是先空出位置再填内容。

## 6. 相机夜景界面与拍摄倒计时

相机界面是参考视频的主线，也是"夜景模式"标题的落点。

### 6.1 界面构成

- 顶部：闪电、HDR、下拉箭头；左侧"夜景"标签（月亮图标）。
- 底部：模式条"夜景/照片/人像/视频" + 快门 + 相册缩略图 + 前后摄像头切换。
- 取景画面持续轻微手持晃动；快速转头时出现运动模糊。

### 6.2 夜景拍摄倒计时

- 按下快门后，快门变为黄色方块（表示曝光中），画面中央出现圆形倒计时：
  圆环上有黄色进度弧，中心是剩余数字，下方深色胶囊提示"夜景模式 · 请保持稳定"。
- 脚本 `camera_countdown(start, seconds, t)` 返回 (剩余数字, 圆环进度)，
  圆环在每个整数秒内推进、数字随整秒递减。
- 倒计时期间允许顶部横幅同时滑入（见 5.1），两者并行不冲突——这是"不打断"
  原则的典型示范。

## 7. 手持真实感：晃动、运动模糊、碎屏

- **手持晃动**：取景/录屏段叠加持续的小幅平移与旋转（幅度很小、低频随机），
  模拟手持呼吸感，不要规则周期摆动。
- **运动模糊**：快速转头/移动的几帧做方向模糊或降清晰，停止后恢复清晰。
- **碎屏裂纹**：参考视频后半段叠加贯穿全片的碎屏裂纹层，暗示手机已摔裂，
  既强化"真实事故"，又服务恐怖叙事。裂纹是固定叠加层，切换界面时保持位置连贯。
- 这些处理都要克制：晃动幅度小、模糊只在快速运动时、裂纹一次成型不频繁变化。

## 8. 落地路径：PIL 关键帧与剪辑

优先用关键帧/后期合成，成本低、可控，不依赖 AI 生成动态视频。

1. 用 `ui_motion.py` 取每帧的缓动进度、矩形插值、透明度与打字时间点。
2. 用 PIL（参考 `ui-clean-frame-repair` 经验）按进度绘制：
   - 卡片缩放：`Image.resize` + 圆角蒙版，圆角半径随进度插值；
   - 淡入淡出：在 RGBA 上调整 alpha 后 `alpha_composite`；
   - 毛玻璃：对背景区域做 `GaussianBlur` 再叠半透明深色层；
   - 键盘/横幅：预制整张图层，按缓动进度改其纵向偏移与 alpha。
3. 输出逐帧 PNG（或直接在剪辑软件里对图层打关键帧），再按时间轴拼接。
4. 界面音（键盘、消息提示、弹窗）与动作帧级对位，见 `style-guide.md` 第 6 节。

脚本本身只输出数值、不依赖 PIL，因此在没有 PIL 的环境也能先把时间轴和参数算好。

## 9. 与消息流 JSON 的衔接

在 `message_flow` 事件上用可选字段描述动效，时间轴与渲染据此对齐，不破坏旧结构：

- `transition`：该事件进入用的动效名（如 `app_open`、`banner_in`、`list_item_fade`），
  取值即 `MOTION_SPEC` 的键。
- `typing`：打字事件可附 `{"text": "...", "base_cps": 6, "jitter": 0.12, "seed": 3}`，
  由 `typing_schedule` 展开逐字时间。
- `duration` 缺省时直接采用 `MOTION_SPEC` 的标准时长，无需手填。

示例事件：

```json
{
  "id": "e20", "type": "notification", "time_sec": 104,
  "window": "相机", "transition": "banner_in",
  "from": "用户_7a3f", "content": "私信了你：[图片]", "intensity": 3
}
```

## 10. 避坑清单

- 时长超过 0.5s 的过渡、匀速线性运动、会打断下层的弹窗——三者都会立刻显假。
- 打字不要整句瞬间出现、不要匀速逐字；必须有拼音状态、按键高亮与不均匀节奏。
- 打开/关闭动画要互逆、曲线方向对应；不要两个界面"硬切"却配下滑音效。
- 通知浮层与背景要同源（同一套毛玻璃圆角），不要横幅一种样式、锁屏另一种样式。
- 手持晃动、运动模糊、碎屏裂纹都要克制且位置连贯，过度处理反而像特效。
- 所有文字（含拼音、候选词、乱码）后期叠加，AI 只出底图与版式。
