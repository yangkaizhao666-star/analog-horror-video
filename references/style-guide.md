## 1. 形式定义

伪装成“第一人称真实设备录屏”的伪纪录片（Found Footage）子类。镜头就是一块屏幕：电脑桌面、手机界面、监控画面。没有摄影师、没有真人出镜、没有旁白解释，观众等同于正在操作设备的人。

成立的根基是“日常性”：观众每天都在用这些软件，因此任何一处细节失真都会立刻出戏。真实感越强，随后的异常就越吓人。

## 2. 视觉系统

### 2.1 UI 载体清单

按叙事功能选用，一部成片通常组合使用 4–6 种：

- **系统登录/锁屏**：开场使用，账号头像 + PIN/密码输入，建立“这是一台真实设备”的第一印象。
- **电脑桌面**：壁纸、任务栏、成排的桌面图标（软件、文档、游戏），交代主角身份与生活。
- **聊天软件窗口**：核心叙事载体。区分群聊（显示人数、群昵称、群公告）与私聊（一对一、更私密、更有压迫感）；包含表情包、图片、文件、语音条、输入中状态、系统提示。
- **浏览器**：虚构搜索引擎主页、搜索结果（资讯、问答、政府/机构条目）、新闻页，用于主角查证与释放误导信息。
- **手机智能门锁/安防 App**：门口监控画面、人形检测、远程开锁按钮、事件日志（精确到秒的密码错误、安防报警、门前逗留记录）。
- **系统弹窗与通知**：物业推送、软件通知、邮件提醒、错误警报，用于打断与强制观众注意。
- **监控/摄像头画面**：夜视、时间码、画面噪点，提供“客观视角”的恐怖证据。
- **合成弹幕**：伪装成视频正在被实时观看的弹幕（文字 + 点赞数），作为画面的一部分，引导情绪、制造“不止我一个人在看”的陪伴感与不安。

### 2.2 视觉基调

- **色调**：夜间冷蓝为主，暗色 UI；危险处用红色（警示按钮、警报小字、红点）。
- **对比**：整体偏暗、低饱和，让红色警报和标题卡的高对比成为视觉焦点。
- **质感**：轻微暗角、噪点、偶发花屏/卡顿，模拟真实录屏与信号劣化，克制使用。
- **一致性**：全片沿用同一套图标、壁纸、窗口样式与字体；窗口位置、任务栏图标保持连贯，像同一次开机录制。
- **文字**：使用系统默认无衬线字体；消息区允许口语化排版，标题卡可用衬线大字 + 红色小字幕次信息。

## 3. 叙事手法

### 3.1 信息分层，由远及近

危险像潮水一样从屏幕外逐级逼近，载体的切换就是距离的缩短：

朋友群（日常）→ 大业主群（远处异常）→ 浏览器查证（理性解释）→ 熟人私聊（身边危机）→ 门锁/警报（门外威胁）。

观众先在大群里“听说”出事，随后在私聊里被熟人求救，最后在门锁界面看到威胁就在门口，代入感逐级升高。

### 3.2 误判链：理性解释逐一失效

真相不要一次给出，而是让一连串“合理但错误”的解释先后出现又被推翻：

咬人 → 以为喝多了 → 以为狂犬病/精神病 → 网传自来水被投毒的谣言 → 警方/急诊占线、秩序失控 → 无法解释的门外异常。

每个解释都符合常识，观众和角色一起被安抚，又一起被新证据推翻，恐惧在反复“放下心—又被吊起”中累积。

### 3.3 日常细节制造真实

- 群聊里穿插与剧情无关的生活流：约球、带饺子、降温加衣、快递、文件传输、物业催办。
- 使用真实的网络表达：缩写、错别字、语音转文字的错误、表情包斗图、群成员调侃、刷屏。
- 角色有各自的说话方式与头像、昵称，而不是统一的工具人台词。

### 3.4 异常信号

在日常界面里用“不对劲”传递恐怖，避免血腥直给：

- **机械重复**：某人反复发送同一句话（如不断催促“出来打球”），语气与时机反常。
- **答非所问/突然离线**：消息逻辑断裂、已读不回、账号在关键处下线。
- **矛盾信息**：亲友发消息说“敲门没人应”，而主角明明在家——暗示门外的“亲友”身份存疑。
- **日志累积**：门锁事件日志逐条增加（密码错误、安防报警、门前逗留），用时间记录显示威胁在持续且升级。
- **倒计时与状态条**：人形检测倒计时、“门外正在输入密码”等实时状态，制造无解的紧迫。

## 4. 节奏模型与节拍表

单集 3–5 分钟，慢热、递进、结尾爆发。以一个 4 分 31 秒的成片为参考：

| 阶段 | 参考时间 | 载体 | 内容与情绪 |
|---|---|---|---|
| 开场建立 | 0:00–0:20 | 登录界面→桌面 | 真实设备开机，音量由低爬升，松弛 |
| 日常铺垫 | 0:20–0:35 | 朋友群/私聊 | 朋友聊天斗图，建立人物与日常 |
| 远处异常 | 0:35–1:15 | 大业主群 | 物业通知、业主听见叫声、发现场图，围观调侃 |
| 误判扩散 | 1:15–2:30 | 业主群→浏览器 | “咬人”被当成狂犬病/醉酒；主角搜索求证，得到理性解释；谣言开始传播 |
| 秩序失控 | 2:30–3:25 | 群聊→私聊 | 110 占线、保安下去查看、急诊爆满；熟人私聊反常复读 |
| 身边逼近 | 3:25–4:10 | 邻居私聊→门锁 | 邻居带伤求救；门锁推送物业警告，“门前有人”、倒计时 |
| 门外威胁 | 4:10–4:28 | 门锁 App | 门外输入密码、密码错误与安防报警日志累积，低频冲击 |
| 悬念收束 | 4:28–4:31 | 黑底标题卡 | 正标题 + “第 N 幕·完”，留钩子 |

情绪温度（紧张度）整体单调上升，只在“理性解释出现”时有短暂回落，靠回落反衬下一次升级。

## 5. 音频模型

音频分析显示：全片无纯静音段，持续有音床；突发声集中在开场进入与结尾高潮。

### 5.1 三层声音

1. **音床（贯穿）**：低频嗡鸣 + 环境底噪，铺满全片，避免任何一秒完全安静。紧张段落提升低频能量（高潮处低频占比可超过 60%）。
2. **界面音（点状）**：消息提示音、鼠标点击、键盘敲击、弹窗、门锁警报，与画面动作帧级对位，是“真实操作感”的主要来源。
3. **突发声（惊吓点）**：音量相对前几秒骤增数倍的敲门声、警报、低频冲击。全片仅 3–5 次，集中在关键转折，滥用会失效。

### 5.2 音量曲线

- 开场：低音量，随设备进入桌面缓慢爬升；第一条强提示音作为“进入正片”的信号。
- 中段：平稳的中等音量，靠界面音与消息节奏维持推进，不做明显惊吓。
- 结尾：先短暂压低（屏息感），再用一次强突发开启高潮，随后音量与低频持续拉升，直到黑场标题卡。

### 5.3 参考数据特征

- 峰值电平约 0.85、整体 RMS 偏低（约 0.05 量级），说明动态范围大、平时克制、突发明显。
- 突发点相对前 3 秒均值可骤增 5–9 倍；高潮窗口低频能量占比显著高于日常窗口。

## 6. 系列化结构

- 以“幕/集”组织长线剧情，每集结尾标题卡标注“第 N 幕·完”，并抛出新疑问。
- 设定可延展的世界观（异常的来源、传播规则、主角命运），让单集恐怖感服务于整条主线。
- 保持固定的主角设备与 UI 风格，形成可识别的栏目招牌；新观众通过开头的强钩子/短前情进入，老观众靠连贯线索留存。
- 每集至少回收一个旧悬念、埋下一个新悬念，维持追更动力。
